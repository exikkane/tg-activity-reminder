# TG Activity Reminder

Telegram-бот для учёта рабочего времени в YouTrack и отдельного журнала работы без задач. Интерфейс на русском. Python 3.12, aiogram, FastAPI, SQLite, Docker Compose.

## Возможности

- Личное подключение YouTrack через OAuth Authorization Code + PKCE, шифрование токенов и обновление доступа.
- Список задач по полям `Responsible` и `Проверяющий`, поиск и пагинация. Для выбора доступны `Stage`: `Ready to work`, `In progress`, `Ready for review`.
- Запись времени в YouTrack от имени сотрудника. Повторные сообщения не создают дубли; неоднозначные результаты проверяются без повторного POST.
- Работа вне YouTrack: описание → продолжительность, хранение в SQLite.
- Напоминания по будням. В примере настроек — 20:00 `Europe/Ulyanovsk`.
- Общий месячный отчёт для администратора: оба источника, суммы по участникам и три CSV — вместе, только YouTrack, только свободные записи.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Подключить аккаунт или открыть задачи |
| `/tasks` | Выбрать задачу |
| `/free` | Описание и время работы без задачи YouTrack |
| `/report [YYYY-MM]` | Месячный отчёт; у администратора общий, у остальных личный вне YouTrack |
| `/teamreport [YYYY-MM]` | Общий отчёт администратора |
| `/cancel` | Отменить ввод |
| `/account` | Посмотреть подключённый аккаунт |
| `/disconnect` | Отключить аккаунт |

Время: `30м`, `1:30`, `2ч`, `1.5ч`. По умолчанию максимум одной записи — 960 минут. Дата свободной записи — день сохранения в часовом поясе пользователя.

## Запуск

1. Создайте Telegram-бота через BotFather и зарегистрируйте OAuth-клиент YouTrack с Authorization Code, обязательным PKCE и точным callback `APP_BASE_URL/oauth/callback`. Нужна версия YouTrack/Hub с поддержкой этого потока.
2. Подготовьте конфигурацию:

```bash
cp .env.example .env
docker compose build
# Вывод — секретный ключ; сохраните его в TOKEN_ENCRYPTION_KEY.
docker compose run --rm --no-deps bot python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

3. Заполните `.env`: `TELEGRAM_BOT_TOKEN`, адреса YouTrack/Hub, OAuth client ID, адрес приложения, callback и ключ шифрования. Для confidential OAuth client дополнительно укажите secret. `APP_BASE_URL` и callback должны совпадать с настройкой клиента.
4. При необходимости задайте `ALLOWED_TELEGRAM_IDS`. В `REPORT_ADMIN_TELEGRAM_IDS` перечислите Telegram ID администраторов общего отчёта; пустое значение отключает общий доступ.
5. Настройте HTTPS reverse proxy на `127.0.0.1:8080` и запустите:

```bash
docker compose config --quiet
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:8080/healthz
```

Ожидается `{"status":"ok","bot_enabled":true}`. Затем откройте бота и выполните `/start`. Не запускайте несколько polling-процессов с одним Telegram-токеном. При прежнем webhook сначала отключите его; приложение не удаляет чужой webhook автоматически.

`compose.server.yaml` — вариант для существующей внешней Docker-сети `youtrack-net` без публикации порта. Перед использованием проверьте имя сети, сервис `timebot` и маршрут reverse proxy.

## Настройки и доступ

Все параметры перечислены в `.env.example`. `REMINDER_DAYS=mon,tue,wed,thu,fri` исключает выходные. Часовой пояс записывается при подключении пользователя; изменение общего `BOT_TIMEZONE` не меняет существующие привязки. `RUN_BOT=false` отключает polling и напоминания для автономных проверок.

Общий отчёт читает реальные Work Items с личным токеном запрашивающего администратора и в пределах его прав. Он включает завершённые задачи и время, внесённое вне бота. История операций бота не прибавляется повторно. Участники отчёта — текущие привязки пользователей; отключившийся пользователь исключается до нового подключения. При ошибке YouTrack общий файл не выдаётся как полный; отдельный CSV свободных записей остаётся доступен.

Свободные записи переживают перезапуск и переподключение. После `/disconnect` история сохраняется, но для доступа нужно вновь подключиться. При истёкшем OAuth уже привязанный пользователь может продолжать вести свободный журнал.

## Данные и эксплуатация

SQLite находится в постоянном Docker volume `bot-data`, путь `/data/bot.db`. Не используйте `docker compose down -v`, если данные нужны. Для резервной копии остановите контейнер и сохраните весь volume либо используйте SQLite backup API. Копирование одного активного WAL-файла `bot.db` не является согласованным бэкапом. Ключ шифрования и `.env` сохраняйте отдельно в защищённом месте.

Один процесс на одну SQLite; приложение блокирует второй экземпляр. После потерянного ответа YouTrack повторный POST не выполняется: используйте кнопку «Проверить запись». Служебный маркер `tg-time:<uuid>` позволяет сверить результат. Не удаляйте журнал неопределённых операций вслепую.

Напоминание резервируется до отправки: это защищает от дублей, но при аварии возможен пропуск. Пропущенные прошлые дни не досылаются. Healthcheck проверяет приложение и фоновые задачи, а не доступность всех внешних API.

Для Telegram можно задать `TELEGRAM_PROXY_URL`; запросы YouTrack остаются прямыми. В `deploy/timebot-telegram-proxy.service.example` есть шаблон SSH SOCKS-туннеля: замените адрес узла и пути, подготовьте закреплённый host key и ключ с разрешением только на Telegram API. Не добавляйте ключи в репозиторий.

## Разработка и проверки

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pytest -q
.venv/bin/ruff check bot tests
.venv/bin/ruff format --check bot tests
```

Тесты используют временные базы и подменённые HTTP/Telegram-ответы. Они не отправляют сообщения сотрудникам и не создают реальные трудозатраты.

## Структура

- `bot/telegram.py` — команды, диалоги, кнопки и polling.
- `bot/youtrack.py` — OAuth, API, фильтры задач и чтение трудозатрат.
- `bot/services.py` — запись времени и напоминания.
- `bot/free_time.py` — свободные записи и личная сводка.
- `bot/reports.py` — общий отчёт и CSV.
- `bot/db.py` — SQLite, шифрование, сохранение состояния.
- `bot/app.py` — HTTP, OAuth callback и healthcheck.
- `tests/` — автоматические проверки; `docs/sources.md` — источники API.

Репозиторий содержит исходники и шаблоны конфигурации. Рабочая база, токены, ключи, выгрузки сотрудников и внутренние материалы кейса в него не входят.
